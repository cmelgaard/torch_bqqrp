# Installation Guide

This project depends on several C++ numerical libraries:

- **Random123**  
- **BLAS++** and **LAPACK++**  
- **RandBLAS**  
- **RandLAPACK**  
- **(Optional) CUDA** for GPU-accelerated `BQRRP_GPU`

To keep everything **self-contained**, all dependencies are:

- cloned into `deps/src/`
- built + installed into `deps/install/`

Nothing is installed system-wide except basic compiler tools.  
If you ever want to start fresh, simply delete `deps/` or the entire repository.

---

# Repository Layout

After installation, your project directory will look like:

```text
torch_bqrrp/
│
├── .gitignore
├── Makefile
├── install.sh
├── INSTALL.md
├── README.md
├── setup.py
├── lisao.py
│
├── torch_bqrrp/
│   ├── __init__.py
│   ├── bqrrp.py
│   └── bqrrp*.so              # compiled PyTorch extension (generated)
│
├── examples/
│   ├── bqrrp_demo.py          # 5000×2800 BQRRP demo
│   └── airbench94_lisao.py    # CIFAR10 using LISAO optimizer
│
└── deps/                      # GENERATED BY install.sh (ignored by git)
    ├── src/                   # cloned dependency sources
    │   ├── random123/
    │   ├── blaspp/
    │   ├── lapackpp/
    │   ├── RandBLAS/
    │   └── RandLAPACK/
    │
    └── install/               # installed headers + libs
        ├── include/
        ├── lib/
        └── cmake/
```

The `deps/` folder is **not tracked by git** and is recreated automatically.

# 1. Recommended Installation Method — Use the Makefile

This is the **only supported installation path** for normal users.

From the repo root:

```bash
make install
```

This will:

1. Install required system packages (compiler, CMake, OpenBLAS, Python headers, etc.)
2. Clone all C++ deps into `deps/src/`
3. Build and install them into `deps/install/`
4. Build the PyTorch extension (`python3 setup.py develop`)
5. Run the BQRRP demo to verify everything works

**CUDA mode is required by default.**  
If CUDA is missing or `nvcc` is not in PATH, `make install` will **fail clearly**.

---

## 1.1 CPU-only build (no CUDA)

If your machine has no NVIDIA GPU:

```bash
make install-cpu
```

This is identical to:

```bash
USE_CUDA=0 ./install.sh
```

It will:

- Build BLAS++ without cuBLAS
- Build RandLAPACK with `RequireCUDA=OFF`
- Build the CPU-only BQRRP PyTorch extension

---

## 1.2 Running tests

```bash
make test
```

This runs:

- `python3 examples/bqrrp_demo.py`
- `python3 examples/airbench94_lisao.py`

---

## 1.3 Cleaning

Remove only dependency sources + installed libs:

```bash
make clean-deps
```

Remove build artifacts (CMake/Python outputs):

```bash
make clean-build
```

Remove *everything generated*:

```bash
make clean-all
```

# 2. Recommended: Python Virtual Environment

Ubuntu 24.04 has “externally managed” Python.  
You **must** use a virtual environment unless you want constant pip errors.

From the repo root:

```bash
python3 -m venv .venv
source .venv/bin/activate

pip install --upgrade pip setuptools wheel
pip install torch torchvision      # or the versions you want
```

Now you may safely run:

```bash
make install
```

or

```bash
make install-cpu
```

Whenever you open a new terminal:

```bash
source .venv/bin/activate
```

# 3. CUDA Behavior (`USE_CUDA`)

### `make install`
→ runs with `USE_CUDA=1`  
→ CUDA *must* be installed  
→ `nvcc` must be in `PATH`  

### `make install-cpu`
→ runs with `USE_CUDA=0`  
→ CUDA will not be used  

Inside `install.sh`:

- `USE_CUDA=1` means:
  - Require `nvcc`
  - Build BLAS++ with cuBLAS
  - Build RandLAPACK with GPU support
- `USE_CUDA=0` means:
  - Build everything CPU-only

# 4. Verifying Your Install

## 4.1 BQRRP Demo

```bash
python3 examples/bqrrp_demo.py
```

This:

- Builds a 5000×2800 random matrix
- Runs BQRRP (and BQRRP_GPU if CUDA was built)
- Prints pivot and shape info

If it runs without error, your build is correct.

---

## 4.2 CIFAR-10 + LISAO Optimizer

```bash
python3 examples/airbench94_lisao.py
```

Optional:

```bash
export CIFAR_DATA=./data
```

This downloads CIFAR-10, trains a small CNN, and prints timing + accuracy.

# 5. PyTorch Installation Requirements  
### (Important for avoiding `libtorch_global_deps.so` errors)

Inside your venv:

```bash
pip uninstall -y torch torchvision torchaudio
```

Install a CUDA-matching version of PyTorch:

```bash
pip install --index-url https://download.pytorch.org/whl/cu121 torch torchvision
```

*(If you want CPU-only:)*

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
```

Verify:

```bash
python - << 'EOF'
import torch, os
print("torch version:", torch.__version__)
libdir = os.path.join(os.path.dirname(torch.__file__), "lib")
print("torch lib dir:", libdir)
print("contains libtorch_global_deps.so?",
      any("libtorch_global_deps" in f for f in os.listdir(libdir)))
EOF
```

You *must* see `True`.

# 6. Troubleshooting

## 6.1 “CUDA was requested but 'nvcc' is not in PATH”

Check:

```bash
which nvcc
nvcc --version
```

If CUDA is missing, either:

- install CUDA Toolkit, or
- run a CPU-only build:

```bash
make install-cpu
```

---

## 6.2 “externally-managed environment”

This means you tried to install Python packages into system Python.

Fix: **use a virtualenv** (see Section 2).

---

## 6.3 Shared library load issues

If Python can’t find libs at runtime:

```bash
export LD_LIBRARY_PATH=$PWD/deps/install/lib:$LD_LIBRARY_PATH
```

---

## 6.4 Remove everything and rebuild

```bash
make clean-all
make install
```

# 7. When Opening an Issue

Include:

- OS version (e.g., Ubuntu 24.04)
- CUDA version (if used)
- Python + PyTorch versions
- Whether you used a venv
- Command used (`make install`, etc.)
- Full terminal log

This helps us diagnose quickly.

# 8. You Should *Not* Run `install.sh` Directly

The supported interface is:

- `make install`  
- `make install-cpu`  

Only advanced users should run:

```bash
USE_CUDA=1 ./install.sh
USE_CUDA=0 ./install.sh
```

Use the Makefile unless debugging.
